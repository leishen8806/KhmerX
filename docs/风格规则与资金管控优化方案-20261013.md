# PayEase / KhmerX 风格规则与资金管控优化方案

版本：v1.0  
日期：2026-10-13  
适用范围：客户端、服务机构后台、持牌机构后台、开放 API 控制台

## 一、设计原则

1. **先状态，后动作**：先告诉用户当前状态、影响和下一步，再展示按钮。
2. **一页一任务**：列表负责查找和批量处理，详情负责单笔闭环，工作台只展示待办与风险。
3. **数据可解释**：所有金额、状态、限额和告警必须能追溯到时间、版本、流水和操作人。
4. **风险动作有阻尼**：资金确认、冻结解除、冲正、权限变更必须二次确认、原因和复核。
5. **测试与生产显式区分**：测试资金、合成资料、沙箱接口不能以生产视觉或文案呈现。
6. **三语一致**：中文、English、高棉语共用同一状态键、错误码和组件，不以拼接字符串实现翻译。

## 二、统一视觉风格规则

### 2.1 色彩令牌

| 用途 | Token | 规则 |
|---|---|---|
| 主色 | `--brand-primary` | `#1769E8`，主按钮、当前菜单、链接 |
| 深色导航 | `--nav-bg` | `#29364A`，固定侧栏背景 |
| 页面背景 | `--surface-page` | `#F4F7FB`，不使用纯白大面积铺底 |
| 卡片 | `--surface-card` | `#FFFFFF`，边框 `#DCE5F2` |
| 正常 | `--status-success` | `#138A5B`，只表示已完成/已核对 |
| 注意 | `--status-warning` | `#B7791F`，补件、临界额度、待复核 |
| 风险 | `--status-danger` | `#C53030`，逾期、冻结、拒绝、扫描失败 |
| 辅助文字 | `--text-secondary` | `#718096`，不用于关键状态 |

禁止用颜色单独表达状态；状态必须同时有文字、图标或状态码。风险红色只用于风险对象，不用于装饰和普通边框。

### 2.2 布局与固定区域

- 后台左侧菜单固定，宽度 280px；一级菜单折叠显示二级菜单，当前二级菜单使用蓝色左边框和浅蓝底高亮。
- 顶部标签栏固定在内容区顶部，高度 72px；滚动只发生在右侧内容区。
- 页面内容最大宽度 1440px，常规间距采用 8px 倍数：8/16/24/32px。
- 卡片保留轻微圆角 12px；左侧菜单、顶部栏接满视口边缘，不使用浮动圆角外壳。
- 移动端保留顶部返回、语言、头像和底部三栏；内容卡片不超过一屏一个主任务。
- 切换二级菜单只更新站内状态，不修改 URL 作为业务状态，不整页刷新；旧内容淡出 120ms，新内容淡入 160ms，避免闪屏。

### 2.3 字体与层级

- 页面标题 28/36px、模块标题 20/28px、正文 14/22px、辅助说明 12/18px。
- 金额使用等宽数字或 `font-variant-numeric: tabular-nums`，货币符号与金额保持同一行。
- 一张卡片只允许一个主标题和一个主动作；次动作使用链接或描边按钮。
- 表格列优先显示：编号、状态、金额/数量、承接方、更新时间、操作；内部 UUID 默认隐藏，详情中可复制。

### 2.4 组件与交互

- 主按钮：实心蓝；危险动作：红色描边；取消/返回：灰色描边；禁用态降低对比度但保留可读性。
- 下拉箭头与按钮文本保持 8px 间距，点击区域最小 40×40px。
- 所有异步操作显示按钮内 loading，不替换整页；成功使用顶部或中部 Toast，失败使用中部 Toast + 可翻译错误码。
- 表单错误紧贴字段显示；网络错误显示“重试”，不得仅显示原始异常字符串。
- 列表空状态说明原因和下一步，不重复显示页面标题、模块标题和相同说明。
- 上传组件显示文件类型、大小、扫描状态和删除/替换结果；扫描失败默认拒绝入库。
- 头像菜单仅显示当前账户、所属公司、岗位、修改密码、退出登录；切换公司直接在弹层选择，单公司不进入中间页。

### 2.5 后台页面模板

```text
固定菜单 + 固定顶部栏
  页面标题 / 面包屑 / 当前权限范围
  主操作区：搜索、筛选、导出、刷新
  数据区：列表或详情
  处理区：状态、负责人、SLA、下一步动作
  时间线：业务事件、审计事件、外部回执
```

列表页必须支持查询、筛选、分页/加载更多、空状态、错误重试和授权导出；详情页必须支持回到列表、刷新、数据范围提示和操作审计。

## 三、资金管控目标模型

资金管控分为四层：**额度控制、余额监管、交易账本、异常与应急**。任何一层异常都不能通过改写历史金额或删除流水来消除。

### 3.1 公司级额度配置

保留当前产品基线：每日放款限额 10,000 USD、每月放款限额 30,000 USD、监管资金余额 20% 预警。建议配置结构：

```text
funding_policy
├── company_id
├── currency = USD
├── timezone = Asia/Phnom_Penh
├── daily_disbursement_limit
├── monthly_disbursement_limit
├── warning_ratio = 20%
├── warning_action = alert | review | freeze
├── effective_at / expires_at
├── version / status
└── approved_by / approved_at
```

规则：

- 只统计最终成功入账的放款；失败、取消、重复幂等请求不计入。
- 所有计算使用整数最小货币单位；不得使用浮点金额。
- 按公司时区计算自然日、自然月；时区变更只影响未来窗口。
- 新配置必须 `draft → review → active → retired`，已生成账单和合同不回算。
- 限额达到 80% 进入重点复核，达到 100% 阻断新放款确认并进入待处理队列。

### 3.2 资金监管分层

| 等级 | 触发条件 | 页面表现 | 系统动作 |
|---|---|---|---|
| 正常 | 可用监管余额 > 30% | 绿色余额卡 | 正常放款 |
| 关注 | 20% < 余额 ≤ 30% | 黄色提示、列入工作台 | 管理员确认，增加复核频率 |
| 预警 | 余额 ≤ 20% | 红色风险事件 + 顶部告警 | 默认暂停自动放款，人工复核后继续 |
| 冻结 | 余额不足、对账异常或人工冻结 | 红色冻结横幅 | 服务端阻断放款，允许查询/还款/对账 |
| 恢复 | 对账完成、余额恢复、双人解除 | 恢复记录 | 解除未来动作限制，不修改历史结果 |

预警必须生成独立 `funding_regulatory_warning` 风险事件，关联资金池、配置版本、余额快照、当日/月累计放款、公司时区、触发时间和影响范围。

### 3.3 放款事务与幂等

放款确认必须在同一服务端事务中完成：

```text
校验会话/公司/角色
→ 校验 KYC、审批、签约、复核状态
→ 锁定 company + funding_policy + request_id
→ 重复 request_id 直接返回原结果
→ 重新计算日/月累计和监管余额
→ 检查限额、冻结和机构状态
→ 写资金分录（借贷相等）
→ 写放款流水、状态快照、审计和风险关联
→ 提交事务并发送异步通知
```

并发请求必须保证：日限额、月限额和监管余额不会被突破；超限返回稳定机器码，如 `FUNDING_DAILY_LIMIT_EXCEEDED`、`FUNDING_MONTHLY_LIMIT_EXCEEDED`、`FUNDING_REGULATORY_FROZEN`。

### 3.4 账本与对账

- 资金流水使用不可变分录：`entry_id`、`request_id`、`loan_id`、借方、贷方、金额、币种、来源、状态、时间。
- 业务状态与资金状态分开：审批成功不等于资金成功，外部回执未知不等于放款成功。
- 对账按日执行，检查内部账本、机构回执、钱包/支付通道三方余额；差异进入“对账异常”，不得手工覆盖。
- 冲正采用新分录引用原流水；禁止 UPDATE/DELETE 原始资金分录。
- 交易查询默认脱敏；导出需要权限、原因、范围和审计记录。

### 3.5 Maker-Checker 与应急

- 放款员只能发起，放款复核员才能确认；发起人与复核人不得是同一员工。
- 解除冻结、调高限额、冲正、补偿、人工标记外部成功均需双人确认。
- Break-glass 权限默认 30 分钟、指定公司/对象/动作，自动过期；不扩大原有数据范围。
- 应急处理保存前后快照、原因、复核人、对账结果和关闭结论。
- 任何异常先进入待处理队列，不允许通过绕权或直接改数据库“恢复正常”。

## 四、资金后台页面优化

### 4.1 资金监管

首屏只显示四项：可用监管余额、今日已放款/月已放款、当前阈值、风险状态。下方再显示资金池、余额趋势、最近风险事件和对账状态。

### 4.2 放款管理

按“待发起 → 待复核 → 已完成 → 异常”分栏；每行显示订单号、客户脱敏信息、实际到账、限额占用、承接机构、SLA 和下一动作。金额确认弹层必须展示费用快照、限额剩余和复核人。

### 4.3 冻结与解除

页面只允许查看原因、影响范围和处理进度；解除按钮必须展示余额核对、对账结果、双人复核和审计预览，不允许单击即解除。

### 4.4 对账异常

按“待核对、待外部回执、差异确认、已补偿、已关闭”展示；每个异常必须有责任人、截止时间、关联流水和处理记录。

## 五、上线验收标准

1. 并发放款不会突破每日 10,000 USD 或每月 30,000 USD。
2. 监管余额达到 20% 自动生成风险事件、通知和审计记录。
3. 预警/冻结状态能阻断新放款，但不影响查询、还款和对账。
4. 重复请求只产生一笔分录和一个放款结果。
5. 外部未知回执不会被标记为成功，能够重试或进入人工核对。
6. 冲正不会修改原始流水，借贷始终相等。
7. 限额、阈值、冻结解除和应急权限均有版本、原因、复核人和生效时间。
8. 后台菜单、状态、告警和错误码支持中文、English、高棉语。
9. 客户端只看到状态与下一步，不暴露内部限额、风险规则和员工信息。
10. 生产发布同时验证容器健康、后台登录、客户端 API、扫描服务、审计检索和回滚。

## 六、实施顺序

### 阶段 1：规范固化

统一设计 Token、状态字典、资金错误码、金额格式、审计字段和风险事件模型。

### 阶段 2：服务端控制

完成公司级配置表、版本生效、并发限额事务、监管余额计算、风险事件、冻结/解除和幂等回放。

### 阶段 3：后台页面

按“资金监管 → 放款管理 → 对账异常 → 冻结与解除”顺序拆分独立页面，统一列表、详情、时间线和导出规范。

### 阶段 4：验收与上线

使用合成客户和测试资金执行正常、80%关注、20%预警、100%阻断、重复请求、并发、对账差异、冲正和应急解除全流程；通过后再进入真实资金合规评审。

> 当前项目仍是测试资金闭环。本方案不会把模拟放款描述为真实金融能力；真实资金接入前必须完成持牌机构、支付通道、合规、安全、对账和灾备评审。

## 七、本轮实现进度（2026-10-13）

- 已完成资金限额状态模型：按柬埔寨时区计算日/月用量、剩余额度、20%预警和硬阻断。
- 已完成后台资金监管、资金流水、对账异常、冻结与解除、风险事件独立页面；风险事件支持确认、关闭和审计。
- 已完成风险事件迁移表与后台接口，放款达到预警线时写入触发快照；超过日/月限额时写入冻结事件后阻断操作。
- 已完成服务端放款流程接入：普通员工放款和公司 Admin 资金操作均使用同一限额校验，并保留 request ID、操作者和审计关联。
- 已完成公司级资金配置：每日/每月限额、预警比例、版本和更新时间持久化；公司 Admin 可在“公司与部门”页面修改，放款流程按当前公司配置校验。
- 新建公司会在同一事务中初始化资金配置，避免新租户出现配置缺失或跨公司继承。
- 风险事件按请求编号和事件类型去重，避免重复点击或重试造成告警噪声。
- 资金配置与风险事件接口补齐稳定机器码（权限、参数、版本冲突、状态冲突），客户端沿用本地化文案展示。
- 资金配置增加业务约束：月度限额不得低于日限额，后台表单与服务端双重校验。
- 已完成风险事件真实数据库闭环测试：触发快照写入、相同请求去重、管理员确认、关闭和重复关闭冲突均已验证。
- 已清理后台左侧菜单重复入口：客户 360° 详情、待补件、补件任务不再作为独立菜单展示，统一从客户列表与 KYC 审核队列进入。
- 已增加菜单契约测试，防止重复二级入口回归，并校验菜单名称唯一。
- 本轮验收：135 项测试中 134 项通过、1 项按现有本地夹具跳过；客户端边界检查、分离构建和差异检查通过。
- 尚未部署生产：风险事件迁移需先在目标环境执行并完成合成资金验收，再进入发布窗口。
