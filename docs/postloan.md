# 贷后任务

公司工作区增加“运营贷后部”（各公司独立），Admin 可增加更多贷后部门，创建“贷后部门主管”和“贷后客服”。主管只管理本部门，客服只处理分配给自己的任务；没有贷款审批、放款或 KYC 查看权限。

检查接口 POST /api/jobs/postloan 使用 POSTLOAN_JOB_SECRET Bearer 密钥，不接受请求指定执行日期。所有活跃公司按 Asia/Phnom_Penh 日历日期执行：
- T-3 生成一次站内还款提醒，错过时在 T-2/T-1 补发；客户登录贷款页面可见。Telegram 按公司独立凭据与客户已验证的订阅发送通用提醒，未配置或未订阅时不发送。
- 到期日创建任务并分配至待办量较少的贷后部门及该部门客服；无客服时保留待分配。
- 到期次日转逾期，同一贷款沿用任务与记录，不每天新建。
- 客服停用或调岗后，下次检查重新分配；主管可手动改派并记录原因。
- 客服记录联系结果、承诺还款日期、下次跟进时间。过了承诺日期未结清，恢复跟进状态。
- 部分还款更新余额，全部还款与任务关闭同一账本事务提交；备注不能减免或关闭债务。
- 乐观锁防止与还款相互覆盖；同一执行重复调用不产生重复提醒或任务。历史跟进仅可追加。

## 定时器接入状态

已提供鉴权接口、scripts/run-postloan-job.mjs 调用脚本和 .github/workflows/postloan-daily.yml 工作流。计划每天 UTC 02:00 执行；须配置两个 Actions Secrets 并手动运行成功后才可确认启用，GitHub 调度可能延迟。Admin 可在“运营贷后工作台”点击“立即执行到期检查”。页面显示最近检查和最近定时调用，未收到定时调用时明确显示未执行。

建议每天柬埔寨时间 09:00（UTC 02:00）运行一次，可安全重试。托管环境配置 POSTLOAN_JOB_SECRET；调用器配置同名密钥与 PAYEASE_SITE_URL。站点当前私有，还需安全配置站点派发凭据 SITES_DISPATCH_TOKEN。不得将密钥放入源码、工作流文件或日志。定时器实际激活后须手动触发一次，验证返回 ok=true 并检查后台时间戳；未验证前不能宣称无人值守每日检查已生效。

任务与日志沿用 D1 公司账本持久化，与测试版每公司最多 100 笔申请的容量约束一致。

## Telegram 接入

Admin 的“Telegram 还款提醒”显示每家公司每个渠道的独立密钥名称。不要使用演示空间的全局 Token。先在 BotFather 创建机器人并配置 Mini App 地址，再把对应 Token 存入页面显示的服务端环境变量。客户在该机器人的 Mini App 内登录贷款账号，点击“同意并启用 Telegram 提醒”，同意消息权限并完成服务器 initData 签名校验。收件人 ID 加密存储，不能由客户端直接指定。客户可关闭订阅。

每日检查创建站内提醒，并将已订阅客户的提醒加入持久化 Telegram 发送队列。只有 Telegram 返回匹配收件人的 message_id 才记录成功；429 可重试，网络超时、5xx 或异常回执记录“结果待核对”，不自动重发。已结清、停用或到期后的历史提醒取消发送。提醒不包含本金、欠款金额、姓名或身份证信息。

本次尚无真实机器人，验收使用合成签名和模拟 Telegram 响应，不代表真实消息已发送。
