# 贷后任务

公司工作区增加“运营贷后部”（各公司独立），Admin 可增加更多贷后部门，创建“贷后部门主管”和“贷后客服”。主管只管理本部门，客服只处理分配给自己的任务；没有贷款审批、放款或 KYC 查看权限。

检查接口 POST /api/jobs/postloan 使用 POSTLOAN_JOB_SECRET Bearer 密钥，不接受请求指定执行日期。所有活跃公司按 Asia/Phnom_Penh 日历日期执行：
- T-3 生成一次站内还款提醒，错过时在 T-2/T-1 补发；客户登录贷款页面可见。Telegram 未接入，不标记为已发送 Telegram。
- 到期日创建任务并分配至待办量较少的贷后部门及该部门客服；无客服时保留待分配。
- 到期次日转逾期，同一贷款沿用任务与记录，不每天新建。
- 客服停用或调岗后，下次检查重新分配；主管可手动改派并记录原因。
- 客服记录联系结果、承诺还款日期、下次跟进时间。过了承诺日期未结清，恢复跟进状态。
- 部分还款更新余额，全部还款与任务关闭同一账本事务提交；备注不能减免或关闭债务。
- 乐观锁防止与还款相互覆盖；同一执行重复调用不产生重复提醒或任务。历史跟进仅可追加。

## 定时器接入状态

已提供鉴权接口和 scripts/run-postloan-job.mjs 调用脚本；未启用外部定时器。Admin 可在“运营贷后工作台”点击“立即执行到期检查”。页面显示最近检查和最近定时调用，未收到定时调用时明确显示未执行。

建议每天柬埔寨时间 09:00（UTC 02:00）运行一次，可安全重试。托管环境配置 POSTLOAN_JOB_SECRET；调用器配置同名密钥与 PAYEASE_SITE_URL。站点当前私有，还需安全配置站点派发凭据 SITES_DISPATCH_TOKEN。不得将密钥放入源码、工作流文件或日志。定时器实际激活后须手动触发一次，验证返回 ok=true 并检查后台时间戳；未验证前不能宣称无人值守每日检查已生效。

任务与日志沿用 D1 公司账本持久化，与测试版每公司最多 100 笔申请的容量约束一致。
