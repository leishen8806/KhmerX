# Codex 开发工作流（代码由 Codex 写，提示词和架构评审由 Claude 出）

## 1. 分工
| 谁 | 做什么 | 不做什么 |
|---|---|---|
| Claude | 写契约、拆任务、为每张任务卡写**可直接粘贴给 Codex 的提示词**；做架构与代码评审；复核验收 | 不替代技术负责人合并；不操作云账号和 GitHub 设置 |
| Codex（苏晨、大旺各自的会话） | 按提示词在独立分支里写代码和测试，提交 PR | 不改范围外文件；不做整文件格式化；不自行扩大需求 |
| 技术负责人 | 确认契约、合并 PR、云资源与密钥、发布决定 | |

## 2. 一张任务从开始到合并
1. Claude 产出提示词（见 §3 模板）与验收标准，放在 `docs/tasks/codex-prompts/`。
2. 开发者把提示词粘给 Codex，在独立 `git worktree` + 分支 `feat/<线>/<编号>` 里执行。
3. Codex 自查：`npm test`、`npm run typecheck`、`npm run lint`、`npm run check:client-boundary`（Flutter 则 `flutter analyze && flutter test`），贴出结果。
4. 提 PR（使用 `.github/pull_request_template.md`）。
5. **Claude 评审**（见 §4），给出"通过 / 需修改"和具体发现；Codex 按发现修改。
6. 技术负责人按风险等级合并（§5）。

## 3. 给 Codex 的提示词模板
```
【角色】你在 KhmerX 仓库（E:\KhmerX\KhmerX）里实现任务 <编号>，只在下面"允许修改的文件"范围内改动。

【背景】<2-5 句：为什么做、现状、相关契约文档路径>

【目标】<可验证的一句话>

【允许修改】<文件/目录清单>
【禁止修改】<文件/目录清单；固定包括：lib/store.ts、lib/domain.ts（除非本任务明确要求）、lib/i18n.tsx、任何构建产物>

【必须遵守】
- 先读 <契约/相关文件>，不要凭印象写。
- 不引入新依赖，除非任务写明。
- 失败响应必须符合 docs/contracts/ARC-00-error-and-envelope.md。
- 不整文件格式化；保持现有文件风格；不删除无关代码。
- 不把密钥、令牌、手机号、证件信息写进代码、日志或测试数据。
- 写操作必须考虑幂等和并发；数据库变更必须带回退脚本。

【步骤】
1. ...
2. ...

【验收标准（必须全部有对应测试或证据）】
- ...

【自查命令（提交前运行并贴出输出摘要）】
npm test；npm run typecheck；npm run lint；npm run check:client-boundary

【交付】
- 分支 feat/<线>/<编号>，PR 小于 400 行（超过请拆成多个 PR，并说明顺序）
- PR 描述：做了什么、没做什么、风险、回退方法
- 遇到需求不明确或需要越出范围时：停止并提问，不要猜
```

## 4. Claude 评审协议（每个 PR 都按此检查）
1. **范围**：有没有改范围外文件、整文件格式化、顺手重构。
2. **契约**：错误体、状态码、`requestId`、命名是否符合 ARC 文档；有没有新增未登记的 code。
3. **安全**：Origin / 鉴权是否强制；有没有把内部异常、SQL、第三方原文返回客户端；日志里有无敏感信息；密钥是否进入代码。
4. **并发与数据**：写操作是否幂等；事务边界；迁移是否向前兼容且有回退；有没有 N+1 查询。
5. **测试**：验收标准逐条有对应测试；有失败路径用例；测试是否真的会失败（不是空断言）。
6. **运维**：日志、指标、开关、降级是否到位。
评审输出：通过 / 需修改；按严重度排序的发现（文件:行号、失败场景、修改建议）。

## 5. 按风险分级合并（技术负责人）
| 等级 | 例子 | 合并门槛 |
|---|---|---|
| 低 | 文档、测试、纯界面样式、脚本 | CI 通过 + 一次快速浏览 |
| 中 | 普通接口、客户端逻辑 | CI 通过 + Claude 评审通过 |
| 高 | 数据库迁移、鉴权与安全、资金相关、机构接口、批量数据脚本 | CI 通过 + Claude 评审通过 + 另一条线同事过目 + 预发演练 |

## 6. 吞吐与瓶颈（需要实测校准）
Codex 能大幅加快"写代码"，但以下环节不会随之缩短：评审与合并、数据回填后的观察期、压测（含持续测试）、备份与故障演练、灰度观察、云资源开通、法务答复。
**第 1–2 天做校准**：用 B0、S2、D1 三个任务实际测量"提示词 → 合并"的平均耗时和返工次数，据此重新估算整体工期；估算依据以实测为准，不以猜测为准。
