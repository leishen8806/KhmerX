## 4. 实施要求

**行为定义(必须满足)**
1. 值恰好为 `+855`(`trim()` 后)的电话字段,**等同于空**:不进入保存请求、不触发"号码格式"错误、不触发服务端拒绝。这与界面上"空时显示 `+855`"的外观一致。
2. 其它输入保持 #81 的行为:客户输入的国际号码原样保留(例如 `+44 7700 900123`);不足位数的值(例如 `+855123`)仍按核心规则判为无效并显示错误;**不要**扩大"当作空"的范围。
3. 必填电话字段(联系人 1、2 等)里只有 `+855` 时,仍按"未填写"处理:提交被拦截,并且指出该字段。
4. 选填且成对的字段(联系人 3、上司姓名+电话):电话只有 `+855`、姓名为空时,视为都为空,不报"请完整填写或全部留空";姓名已填、电话只有 `+855` 时,仍报"需成对填写"。

**推荐做法**:恢复 `change()` 中对 `+855` 的规整(a82b563 的一行逻辑)。草稿在服务端不可能含 `+855`(服务端一直拒绝),所以不需要处理加载路径。若你发现其他入口也会把 `+855` 写进状态(例如粘贴、浏览器自动填充、`accept` 回填),在该入口同样规整,并在 PR 里说明。若你选择别的做法,必须满足上面 4 条,并在 PR 描述里说明为什么。
