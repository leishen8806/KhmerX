## 本机副本流程(Claude 依据 `L1-G-gray-fixture.md` §7 的既有做法起草;窗口内由 OPS 人工执行,不是新的批准)
**为什么是 `d1` 和 `r2`:** `server.mjs` 的持久化目录是 `/data/d1`(SQLite)和 `/data/r2`(KYC 对象存储);启动时的迁移与"清理未完成上传"会改动这两处。`config.json`(含密钥)、`gray-closed`、扫描器令牌文件在重建中不会被容器改动,**不放进副本**,避免多留一份含密钥的文件。
**先在窗口前做只读核对:**
```bash
du -sh /opt/payease/data/d1 /opt/payease/data/r2
df -h /opt/payease | tail -1
```
副本所在分区的剩余空间须大于两目录体积之和的 2 倍,且做完副本后磁盘使用率仍低于 85%;否则停止并报告,不要继续。
**窗口内(应用停机后才能做一致的副本,SQLite 有写锁):**
```bash
cd /opt/payease/app
docker compose -f deploy/standalone/gray/compose.gray.yaml stop payease
umask 077
ts=$(date +%Y%m%d-%H%M%S)
tar -C /opt/payease/data -czf /opt/payease/loadtest/rebuild-before-$ts.tgz d1 r2
sha256sum /opt/payease/loadtest/rebuild-before-$ts.tgz        # 记录哈希
ls -l /opt/payease/loadtest/rebuild-before-$ts.tgz            # 记录大小与权限
tar -tzf /opt/payease/loadtest/rebuild-before-$ts.tgz | head -3   # 只看路径,确认非空
```
- 目标目录 `/opt/payease/loadtest` 必须**已存在**且为 1000:1000、700(这是 O4 里"待核对"的那个目录)。**不存在就停止并报告,不要创建。**
- 副本文件权限必须是仅属主可读写(`umask 077`),**不得**放在 `/tmp` 或其他人可读的路径。
- 任何一步报错就停止并报告,**不要重试到成功**;`tar` 失败时先确认应用仍处于停止状态再报告。
- 副本做完并记录哈希后,才继续 O2 执行单 §4.4 的替换制品与重建。
**保留与删除:** 副本保留到 O2 与 O6 通过且负责人确认之后;**OPS 不得自行删除**。灰度只有虚构数据,但副本仍按敏感文件处理:不进 Git、不进日志、不外传。
**从副本恢复(仅在怀疑数据损坏时,且须负责人批准):** 停止应用;把现有 `d1`、`r2` 改名保留(例如加 `.bad-<时间>`);用 `tar -C /opt/payease/data -xzf <副本>` 还原(以 root 解压以保留属主);启动应用并核对 `/healthz`、`/readyz`。**不是**回退制品的步骤:回退制品见 O2 执行单 §6。
