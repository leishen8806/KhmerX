# 线上 SSO 设备验收清单

适用入口：`/team/login`
目标：验证“认证 → 公司上下文 → 权限范围 → 业务操作 → 审计 → 退出”完整闭环。

## 1. 登录与默认公司

- 使用已授权后台账号进入 `/team/login`，完成 ChatGPT SSO。
- 首次进入确认自动进入默认/上次公司，不出现短暂的公司选择页。
- 右上角头像显示当前公司、账号和角色。
- 刷新页面后公司上下文、菜单和数据保持一致。

## 2. 多公司切换

- 从右上角头像打开公司切换器，进入第二家公司。
- 确认公司名称、入口代码、菜单权限和数据全部切换。
- 返回第一家公司，确认第二家公司数据不可见。
- 退出后重新登录，确认恢复最近一次公司。

## 3. 角色与数据范围

- 公司管理员：可管理组织、员工、机构和平台配置。
- KYC 审核员：只能看到指派给自己的 KYC 案件。
- 机构审批/复核员：只能看到所属机构贷款，审批人与复核人不能相同。
- 放款员/放款复核员：只能处理所属机构放款，发起人与复核人不能相同。
- 审计员：只读业务和审计数据，所有写操作应被拒绝。

## 4. 业务闭环

使用一组唯一 UAT 客户和贷款编号，逐步记录：

1. 客户注册并完成 KYC 上传。
2. KYC 审核通过或退回，客户端状态回写。
3. 客户提交贷款申请并确认费用。
4. 客户完成签约。
5. 机构审批员初审，持牌机构复核员复核。
6. 放款员发起放款，放款复核员复核放款。
7. 生成账单，登记还款，完成结清/贷后状态回写。

每一步同时保留三类证据：页面结果、网络响应、后台数据/审计记录。

## 5. 退出与安全

- 点击退出后确认不闪现公司选择页，直接回到登录入口。
- 使用旧页面、旧 API、旧会话访问，均应被拒绝或重定向。
- 停用员工后立即撤销会话，重新访问返回未授权。
- 角色或机构变更后重新加载，数据范围即时生效。

## 6. 通过标准

- 页面布局无横向溢出，搜索/导出/筛选控件基线一致。
- 公司、部门、机构、角色、员工、业务和审计数据不串租户。
- 所有关键操作都有操作人、公司、前后值、原因、时间和请求追踪号。
- 页面、网络和服务端三类结果一致，才能标记该步骤通过。

## 8. 受控 UAT 闭环运行时回归

- 本地新增运行时测试覆盖 `seed → 幂等重放 → clear`，并校验合成 KYC、签约、放款、账单结清、租户隔离、错误令牌拒绝和清理后数据库计数。
- 清理逻辑使用真实 KYC case id，并在受控 UAT 租户清理前将 case 暂置为 draft，以遵守 KYC 审核历史的 append-only 约束；审核历史随后完全清除，`uat_closure_batches` 与平台审计记录保留。
- 失败路径回归覆盖：分配部门异常时，已创建的合成账号、分配记录和 KYC 草稿均回滚，不留下半成品数据，也不遮蔽原始错误。
- 清理接口增加工作区版本前置条件与批内 CAS；版本冲突返回 409，贷款/账务数据保持不变，不会执行部分清理。
- 清理未知批次返回幂等结果且不写入审计，重复点击或重试不会产生脏数据。
- 运行时验证普通审核员使用正确令牌仍被拒绝（403），只有平台管理员可执行受控入口。
- 运行时验证受控开关关闭时返回 404，确认默认 fail-closed 且不触发业务数据变化。
- 运行时验证已有业务数据的 UAT 租户拒绝新批次（409），保持原有数据不变。
- 线上 `UAT_CLOSURE_ENABLED` 与令牌仍保持关闭/未配置；未向线上写入合成客户、贷款或审核数据。线上业务闭环仍需在专用 UAT 租户开关经审批开启后复测。
