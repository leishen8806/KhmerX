# K1：客户 KYC 文案与内部信息边界

范围仅 H5/Mini App KYC。分支从当前 origin/main a483612 开始，与 R0 PR 独立；不部署、不改接口和存储、不调用线上业务写操作。

## 实现

- 客户不渲染 KESS、模拟手机号、权重／单元格来源、注册来源中的测试说明；审核端保留。贷款、还款、签约等非 KYC 页面原有测试资金声明不变。
- 静态文本、状态、按钮、上传说明、aria-label/placeholder/title、校验错误接现有 legacyText 与 KYC 补充词典；H5/mini 同样生效。时间使用当前语言和 Asia/Phnom_Penh。
- 自由输入、审核员意见、IDs、文件元数据和合同正文不翻译。选择项只翻译显示标签，提交值不变。行业／职位等复用 options.json 已有柬语；部分字段复用 mobile ARB 译文。
- 省／区县没有可靠柬语名时保留数据中的拉丁地名；不是声称全部专名已有柬语。为避免旧词典按斜线误拆字段标签，KYC 明确映射省、市、收入证明等复合标签。
- 375px 高棉语卡片的绝对定位状态会覆盖长标题，增加仅 km 的静态布局覆盖；不改变其他语言旧布局。

## 验证与限制

4项新回归先失败后通过：客户／审核视图边界、H5/mini 的14步骤 en/km文本与属性、输入保留、错误与时间／动态上传提示。最终 npm test 436通过、10跳过、0失败；typecheck、build:separated通过（leaks0）；lint0错误、679警告。

本机隔离 Miniflare 使用临时 D1/R2、虚构客户和1px图片，375px高棉语检查包括分类、校验、上传和补件重新提交；重新提交后实际API状态为submitted，合成审核后为approved。审核决定由本机fixture执行，不是线上人工验收。

原有 opt-in tests/kyc-local.test.mjs 额外启用时未通过：空地址400的错误码实际REQUEST_FAILED，测试期望INVALID_REQUEST；另一次独立诊断到跨客户附件预期404但实际400。未放宽或修改这些原断言，默认门禁仍跳过该项，不声称端到端测试全绿。重复使用合成号码还会触发429，因此不能复用数据冒充新流程。

文档不一致／范围外：评审行号是展开格式，当前源码压缩；needs_info首次加载会覆盖URL分区并按旧审核意见跳回personal（C5，未改）；签名／测试合同分支已被现有slot过滤，K1不改共享签名组件或正式合同。R0导航修复在PR #75，不夹带到K1。

待母语复核（未获批准）：所有新增KYC补充词典的长提示，尤其授权／定位／最终贷款决定、文件大小与PDF下载、24小时预计审核提示；沿用的资料授权译文及行业/学历枚举；缺失柬语的省／区县专名。未编造缺失地名译文，未将现有译文标为母语已审。两批PR如同时合并，须保留R0导航修复与K1翻译，不以任一整文件覆盖另一方。
