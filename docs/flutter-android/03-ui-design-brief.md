# KhmerX Android 客户端 · UI 与交互设计任务书（交给 Codex）

- 版本：草案 v1（2026-10-07）
- 写给：负责 UI 与交互设计的 Codex
- 必读依据：`01-requirements.md`（功能需求）、`02-api-contract.md`（接口与状态机）
- 下游：设计成果将由技术方案阶段（Claude）对接为组件与路由，再由 Trae 实现代码。**请不要写业务代码，也不要改动 `app/`、`lib/` 等现有目录。**

## 1. 产品背景
KhmerX 是面向柬埔寨市场的小额借款服务。客户用手机号验证后完成 KYC、签约并申请借款。用户以高棉语为主，需支持英文，管理端可开启中文。用户中包含对金融产品和数字操作不熟悉的人群，**清晰、可信、少步骤**比花哨更重要。

## 2. 设计目标与原则
1. **可信与克制**：金融场景，信息明确，避免夸张营销与诱导性动效。
2. **状态驱动**：用户永远知道“我现在在哪一步、下一步做什么、等待谁”。
3. **容错与可恢复**：任何步骤可中断、可恢复，草稿不丢；错误说明具体且可操作。
4. **本地化优先**：高棉文是主要语言，文案长度、行高、断行都按高棉文设计，不以英文为基准。
5. **安全可见但不吓人**：隐私与授权说明清楚，敏感操作有确认。
6. **一手操作**：竖屏手机，核心操作区在拇指可达范围。

## 3. 视觉与品牌基线
沿用现有 H5 样式库，保持三端一致：
- 品牌色 `#1677FF`，正文 `#172033`，辅助文字 `#667085`。
- 输入框与主按钮高度 **48px**，卡片圆角 **16px**。
- 支持浅色与深色主题，遵循系统设置。
- 尊重“减少动态效果”系统偏好。
- 参考样式库：`https://payease-style.khmerx.org/?release=6b87e79958fd`（若无法访问，以现有 `app/globals.css` 与 `components/mini-shell.tsx` 的视觉为准，请只读取参考）。
- 请输出一套 **设计令牌**（颜色、字号、行高、间距、圆角、阴影、状态色），区分浅/深色，包含**高棉文字阶与行高**。

## 4. 平台与约束
- Android 手机竖屏，参考画布宽度 360–412dp，需验证小屏（320dp）与大字体（系统字体 130%/200%）。
- 触控目标 ≥ 48dp；对比度满足可读性。
- 全局 `FLAG_SECURE`：设计中不要依赖截图分享；任务切换预览会被遮挡，请设计“切后台遮罩”的外观。
- 语言：en / km / zh，界面需在三语下都不破版；**长高棉文与长英文**要有换行策略。
- 金额为 USD，两位小数；日期格式统一。

## 5. 需要设计的信息架构

**底部导航（4 项）**：首页 / 借款 / 消息 / 我的。
> 注：“消息”本期只展示贷款事件时间线（来自 `state.events` 的客户可见部分）与系统提示，**不含推送**。如你认为 4 项过多，可以建议 3 项并说明理由。

**页面清单**
1. 启动与会话恢复（含骨架屏）
2. 选择公司：扫码、粘贴链接、已用公司列表
3. 登录入口：手机号输入、验证码、密码登录、切换登录方式
4. 验证码输入页（倒计时、重发、错误状态、无 Telegram 说明）
5. 设置密码（强制）
6. 找回密码
7. 首页（状态驱动，见第 6 节）
8. 借款记录列表、借款详情（账单、时间线、合同入口）
9. KYC 总览（分组进度、完成度、缺项）
10. KYC 分步表单：个人与身份、紧急联系人、工作与资产、收款账户、授权确认
11. 材料上传：拍照/相册、取景引导、压缩进度、失败重试、缩略图预览、替换
12. 申请借款：额度与期限选择
13. 费用账单确认
14. 条款阅读（滚动读完才可同意）与手写签名画布
15. 申请提交结果与进度
16. 我的：个人信息概览、语言、修改密码、公司切换、退出、关于
17. 通用组件：错误页、离线横幅、空状态、加载骨架、确认弹窗、底部抽屉、Toast/Snackbar

**功能开关页面**（默认隐藏）：提现、还款，需设计但标注为“开关控制”。

## 6. 关键流程与交互要求

### 6.1 首页（状态驱动）
- 一张主卡片显示当前阶段与**唯一主按钮**，映射见 `01-requirements.md` 第 5 节（13 种条件）。请为每种条件设计卡片内容与文案占位。
- 下方是贷款摘要与待办提示；顶部显示公司名与语言入口。
- 弱网/缓存态：显示“最后更新时间”，下拉刷新。

### 6.2 登录
- 路径：手机号 → 同意接收 Telegram 验证码（勾选）→ 发送 → 输入 6 位码。
- 说明必须清楚：验证码会发到 **Telegram 的 “Verification Codes” 会话**，需安装 Telegram 且号码已注册。设计一个“打开 Telegram”的辅助按钮与无法收码的帮助说明。
- 状态：发送中、倒计时（60 秒）、过期（5 分钟）、错误次数、被限流（显示倒计时）、网络失败。
- 已设密码用户默认进入“密码登录”，可切换“验证码登录”。
- 手机号输入：国家区号选择，默认柬埔寨 +855，号码格式化、粘贴友好。

### 6.3 KYC
- 总览用**分组进度**展示（5 组），每组有完成/缺项/锁定状态。
- 表单：**每步可保存并稍后继续**；离开前自动保存；字段错误就地提示；选择类字段用底部抽屉或全屏选择器，选项标签为“English / ភាសាខ្មែរ”风格需适配当前语言。
- **材料上传**是核心体验：取景引导（证件框、人脸框）、光线与清晰度提示、自动压缩、进度与取消、失败重试、替换与预览。自拍/签名/车辆照不允许 PDF，请在界面上就体现这一限制。
- 条件字段（车辆、住房）动态出现，说明“车辆材料三选一”。
- 状态展示：审核中（锁定）、需补件（突出审核意见并定位到相关分组）、已通过、未通过。
- 授权同意与定位说明：用简短条目 + 详情展开，定位明确为“自愿”。

### 6.4 申请、账单、签约
- 额度（30/50/100/500 USD）与期限（14/28 天）选择，实时展示**服务端返回的报价（Quote）**明细（客户端不计算，计算期间显示加载态）。**依赖 CR-001 无副作用报价接口：现有后端尚不存在，2026-10-07 已决策新增。** 流程固定为：选择 → 获取报价 → 展示费用 → 用户确认 → 创建申请。**创建申请之前，用户必须已经看到费用**；报价过期时需要“报价已更新，请重新确认”的状态。
- 账单页：本金、费用、到账金额、应还总额、期限、到期日；强调“到账金额”与“应还总额”的差别。
- 条款阅读：长文滚动，读完才激活“同意”；提供字号调整。条款目前为中文，请设计“条款为中文原文”的提示位置。
- **手写签名画布**：全屏横向或大面积竖屏，清除/重签/预览；空签名不可提交；笔迹粗细与平滑。
- 提交后的结果与“等待机构审批”状态页。

### 6.5 错误与异常（请逐一设计）
- 会话过期：不丢当前输入，登录后回到原位。
- **409 数据已变化**：这是正常分支，设计“已为你刷新，请确认后继续”的轻提示，而不是错误页。
- 限流（429）：倒计时。
- 离线：横幅 + 可读缓存 + 写操作禁用并说明。
- 服务暂不可用（503）。
- 无 Telegram 用户的引导。

### 6.6 确认类操作
提现、还款（开关控制）与最终“提交申请”使用确认弹窗：展示贷款编号、状态、金额，按钮文案明确。成功状态以服务端为准，弹窗关闭前不要显示成功。

## 7. 内容与文案规则
- 所有界面文案需**三语占位**（en / km / zh），可先以英文与中文给出，高棉文由本地化团队审校；请标注每条文案的**最大字符/长度预算**。
- 避免技术术语；金额与日期始终带单位。
- 服务端返回的中文状态说明**不直接展示**，界面使用本地化状态文案；请为每个状态给出一句话说明（见 `02-api-contract.md` 3.4）。

## 8. 交付物清单
1. **设计令牌**（浅/深色、三语字阶、间距、圆角、状态色）。
2. **组件库**：按钮、输入框、选择器、卡片、状态标签、进度条/分步器、弹窗、抽屉、Toast、空状态、骨架屏、上传卡片、签名画布。每个含状态（默认/聚焦/错误/禁用/加载）。
3. **全部页面高保真稿**（第 5 节清单），含浅/深色、km/en 两种语言、正常/加载/空/错误状态。
4. **交互说明**：页面跳转图（用户流程图）、手势、动效（含“减少动态效果”下的替代）、键盘与焦点行为。
5. **状态矩阵**：首页 13 种条件 × 内容与主按钮；KYC 5 种状态 × 界面。
6. **文案表**：每个文案的 key、三语文本、长度预算、使用位置。
7. **无障碍清单**：对比度、最小触控、字体缩放（130%/200%）下的版式。
8. **可切图的资源与图标清单**（SVG 优先），并标注需要的 Material 图标。
9. **设计说明**：关键决策与取舍，以及你对本任务书的疑问或建议。

## 10. 与技术方案的对接约定（避免返工）
- 页面与组件命名用英文 kebab/camel 一致的 id，便于直接映射为 Flutter 路由与 Widget。
- 每个页面标注**它依赖的接口**（见 `02-api-contract.md`）与需要的数据字段，方便技术方案划分数据层。
- 任何需要**后端新增能力**才能成立的设计（例如邀请码、推送、条款译文、错误码），请**单独列出并标注“依赖后端”**，不要默认存在。**已确认的后端增量只有 CR-001（报价）与 CR-002（`assetlinks.json`）**，其余均不存在。
- **KYC 草稿**：当前页未保存的编辑只在内存，分组“继续”时保存到服务端；强杀进程可能丢失当前分组未保存输入，请在 KYC 流程里设计清晰的“已保存/未保存”提示与“Save & Exit”。
- **KYC 规则版本不一致**时 KYC 只读，并显示“请升级应用”提示页（需要设计）。
- 所有表单字段与选项以 `02-api-contract.md` 4.5 为准，设计中不得新增或删除必填项。
