## 1. 产品是什么（已定）
**开放式小额贷款 Android APP。** 任何用户都能注册、登录、借款；用户**不选择、不关联机构**，机构由管理后台关联，新用户归属由后端分配。

| 已定 | 内容 |
|---|---|
| 第一版登录方式 | 手机号 + 验证码（验证码经 Telegram 发送）、手机号 + 密码 |
| **不进第一版** | Google 登录、Facebook 登录（以后单独做，需新契约；必须再绑手机号） |
| 第一版范围 | 登录 → 首页 → 贷款合同**只读** → 语言切换（高棉语 / 英语 / 中文） |
| **不做** | 还款、放款、推送、罚息（后面阶段，且要先过安全门禁） |
| 分工 | **Trae 写全部 Flutter 代码**；Claude 只做契约和架构；Codex 做 UX 与独立验收 |

## 2.1 第二阶段（KYC，2026-10-12）
契约 `76-P2-kyc-contract.md`；真实后端接口无需改动。已实现并实测（模拟器 + 本地后端）：
- 首页「开始验证」→ 总览（状态、审核意见、5 个分组完成度）→ 分组表单（km / en / zh）→ 拍照 / 相册上传 → 保存草稿 → 提交；`submitted` / `approved` / `rejected` 只读；`needs_info` 显示审核意见并可修改重提。
- 与服务端一致的本地校验（缺项、电话格式、联系人 3 全填或全空、车辆材料三选一、住房证明等）；缺项时不发请求并列出缺项。
- 版本冲突（409）自动重新加载并提示；服务端 `ruleVersion` 与 APP 内置选项版本不一致时提交被拒（失败关闭）。
- 用真实后端跑通完整提交：`node scripts/dev-app-backend/kyc-smoke.mjs`（注册 → 上传 4 张材料 → 保存 → 提交 → 过期版本 409 → 提交后锁定 409 全部通过）。
- 体验打磨（10-12）：启动画面（原生蓝底 + Flutter 品牌动画页，至少显示 0.9 秒）、新图标、登录页品牌头、圆角输入框/卡片主题；资料填写改为分步向导（每页 ≤3–4 项，进度条、上一步/下一步、本步必填校验、自动存草稿、从第一个未完成步骤继续）。截图 `status/69–76`。
- 自动化：`flutter analyze` 0 问题；405 个测试全部通过（新增 KYC 校验/仓库/控制器/页面测试）。

**未做 / 待办**：授权文案是占位文本（待法务，DEC-6）；高棉语译文需母语者复核；材料只支持图片（不含 PDF）；`rejected` 后无重新申请（CR-010，后端无接口）；定位上报与手写签名不在本阶段；通知设置属于后面的推送阶段。
