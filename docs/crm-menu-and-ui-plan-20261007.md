# KhmerX CRM 后台菜单、独立页面与上线验收规划

版本：2026-10-07  
范围：服务机构后台、持牌机构复核后台；不改变客户 Mini App 和 H5 的业务规则。

## 1. 当前实现基线

当前代码已经具备：工作台指标、公司/员工/岗位权限、KYC 审核与补件、客户列表与 360° 摘要、贷款审批与签约、放款/还款测试流水、贷后任务、Telegram 通知、工单、报表导出、业务 Bot、费用配置、MFA、紧急访问、审计完整性校验、客户端语言配置。

当前 `/team` 仍把多个队列集中在一个客户端组件中，部分菜单是锚点或队列切换，而不是完全独立的业务页面。下一阶段按下表拆成独立页面；每页保留统一 CRM 壳层、权限守卫、加载态、空态、错误态、审计事件和返回路径。

状态标记：

- **已实现**：代码已有可用组件/API，可直接拆页验收。
- **需拆页**：已有能力，但当前通过队列或锚点展示。
- **规划开发**：菜单和闭环已定义，尚未形成完整页面/API。

## 3. 统一页面结构

每个二级页面采用同一结构：

1. 固定左侧一级菜单；
2. 固定顶部标签栏：面包屑、语言国旗、环境、公司/岗位/账号、退出；
3. 内容区：页面标题、说明、筛选区、指标卡、主表/详情抽屉、操作栏；
4. 所有异步操作使用骨架屏或局部 loading，不整页跳动；
5. 页面状态必须具备 loading、empty、error、permission-denied、success 五类；
6. 所有写操作返回稳定 `code`，前端文案按后台语言本地化；
7. 写操作必须显示影响范围、版本号、原因输入和成功后的数据回读。

## 4. 前端分阶段开发与验收

### 阶段 0：壳层与路由基线

- 建立 `CrmShell`、`CrmSidebar`、`CrmTopbar`、面包屑和二级页面注册表。
- 独立路径仅用于页面寻址；页面内业务状态不得依赖整页刷新。
- 验收：桌面/窄屏菜单、固定顶部、内容区滚动、语言/头像/退出、返回路径均通过。

### 阶段 1：已实现能力拆页

- 工作台、客户列表/360、KYC 队列、贷款申请、放款、还款、贷后、通知、工单、报表。
- 验收：每页完成“列表 → 详情 → 操作 → 服务端写入 → 回读 → 审计 → 返回列表”。

### 阶段 2：组织与安全

- 公司/部门、员工角色、字段权限、持牌机构、语言、文件扫描、MFA、审计。
- 验收：不同岗位登录后菜单、数据、按钮、API 同时受限；越权请求返回稳定错误码。

### 阶段 3：资金与风控

- 限额、预警、冻结、流水、对账异常、风控事件、审批协同。
- 验收：双人复核、版本冲突、重复请求、失败重试、审计链和导出均可回放。

### 阶段 4：内容运营与报表

- 产品、规则版本、Bot、三语模板、新闻、资讯、帮助中心、自定义报表。
- 验收：草稿/审核/发布/撤回闭环，历史业务引用旧版本不被改写，导出脱敏。

### 阶段 5：上线回归

- 本地：全量单元、集成、迁移回放、构建。
- UAT：Admin、KYC 主管、机构复核员、放款复核员、贷后角色各一套账号。
- 线上：域名、Caddy、容器、数据库迁移、扫描器、第三方接口和 OA 共存检查。
- 每个页面至少验证：首次进入、刷新、返回、重复点击、会话过期、无权限、空数据、错误恢复。

## 5. 页面验收模板

每个页面交付时必须附：

- 页面截图或静态原型对照；
- 菜单权限矩阵；
- API 请求/响应与机器错误码；
- 数据库写入前后样本（脱敏）；
- 操作审计记录；
- 正常、空、错误、无权限、重复提交五类测试结果；
- 浏览器桌面宽屏、窄屏和 Telegram WebView 检查结果。
