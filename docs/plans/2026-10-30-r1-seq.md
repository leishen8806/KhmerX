# R-1: `team_audit.seq` and manifest v3

## Boundary

New audit writes allocate a monotonic database sequence with `MAX(seq)+1` in the
same insert statement. Manifest v3 orders and bounds by `seq`; its digest bytes
remain the v2 five-field tuple (`id`, `actor`, `action`, `detail`, `created_at`),
so v2 manifests verify with the original timestamp/id algorithm.

The migration is additive and local-only for this plan. Existing rows without a
sequence are reported as `needsManualReview`; R-2 supplies the local/backup
backfill. No remote or production migration is included.

## Verification matrix

- same-millisecond writes retain insert order;
- an older timestamp committed later is retained by sequence order;
- batch inserts produce consecutive sequence values;
- edits and deletes change the digest;
- v2 tuple serialization is unchanged.
