## 3. 数据闭环验收结论

### 已通过（隔离 UAT 合成数据）

`客户注册 → KYC 提交 → KYC 审核 → 贷款申请 → 机构初审 → 独立复核 → 签约 → 放款 → 账单生成 → 部分还款 → 全额还款 → 贷款结清 → 客户/员工端状态回写 → 审计事件`

该链路已由集成测试写入并重新读取状态，且验证了重复放款幂等、跨公司隔离、角色数据范围和双人复核约束。

### 线上共享站点当前边界

线上 KYC、审批、已放款还款队列当前均为 0 条，页面显示正确的空数据态；因此本次没有把“线上空队列”误报为已完成线上写入闭环。要做可视化线上写回验收，需先在专用 UAT 租户执行一次合成夹具 seed，再用客户端和后台端各自回放同一订单。

## 4. 问题与优化建议

1. **验收阻塞项（环境数据）**：共享线上租户没有预置合成订单，无法在不污染共享数据的前提下完成浏览器端写入回放。建议新增仅限 UAT 的 `seed → replay → purge` 操作，并在审计中记录 seed 批次号。
2. **性能观察项**：部分深链首次加载约 5–10 秒，刷新后恢复；建议为页面入口增加加载骨架、接口耗时埋点和超时提示，但不影响当前功能正确性。
3. **持续验收项**：真实 Telegram、真实证件、真实支付/银行接口不纳入本次测试；上线前应由持牌机构在隔离沙箱完成供应商回调、MFA 和资金对账演练。

## 5. 结论与放行建议

- 代码、自动化业务闭环、权限隔离、安全契约和线上页面结构：**通过**。
- 共享线上租户的浏览器端“合成数据写入回放”：**待专用 UAT seed 后补验**，不是代码失败。
- 当前版本可进入 UAT 放行；生产放行前必须补做一次专用租户的客户端提交、后台审核通过/退回、状态回写、账单结清和审计导出全链路，并保存订单号、请求追踪号和审计记录。

## 6. 本地黑盒补验记录

- 直接运行普通 `npm run dev` 后，未注入站点身份的 `/api/state` 和 H5 登录服务按预期拒绝请求（`AUTH_REQUIRED`/未配置服务），未将此认证门禁误判为业务失败。
- 使用项目规定的 Miniflare 测试启动器并注入合成身份后，黑盒脚本可进入交易链路；其逾期通知断言受本地共享 seed 的既有通知记录影响而中止。该问题属于测试夹具隔离不足，建议脚本启动时使用唯一 workspace 或清理批次，而不是修改业务逻辑。
- 因此本次放行依据仍以隔离数据库的 68/68 事务测试和 10/10 HTTP 契约测试为准；黑盒夹具问题列为 UAT 环境整备项。
